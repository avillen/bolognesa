# Project status

Last reviewed: 2026-10-13.

Bolognesa is an early self-hosted media center built with Phoenix LiveView, Ecto, PostgreSQL, and Oban. The repository includes local Docker Compose development and a generic Linux Compose deployment. Movie and series libraries, scanning, technical inspection, TMDb identification, catalog browsing, authorized direct playback, an optional FFmpeg/HLS path, and individual local music listening are implemented.

The sidebar lists configured libraries by their stored names with movie, music, or series icons, including empty libraries. Catalog lists, searches, pagination, and availability counts are scoped to the selected library. Detail navigation retains that selection; work details and playback versions remain shared across libraries. Creating a library updates the sidebar immediately.

The library screen refreshes scan progress and inspection counts asynchronously after hints explicitly emitted by application use cases through `LibraryStatusNotifier`, following successful persistence. Recovery use cases also notify changes confirmed before a later recovery transaction fails. Repositories return persisted results and never publish PubSub hints. Subscriptions and reads are independently authorized; PostgreSQL remains authoritative. Hints are best effort: a lost notification or interrupted subscription can leave an open tab stale until another hint or reload/reconnect.

The shared `Infrastructure.Services.PubSubNotifications` transport accepts context-owned topics and messages and normalizes availability errors. Libraries retains its status payload, logging, and best-effort delivery policy.

LiveDashboard is available at `/dev/dashboard` in all environments. HTTP requests and LiveView mounts require a verified administrator session; the mailbox preview remains development-only.

## Local music listening

Create a music library, scan it, and browse individual tracks with embedded title/artist/album tags or filename fallbacks. The music page supports library scope, search, pagination, processing/error feedback, refresh, and explicit import retry. Selecting a current ready track presents a native audio player without autoplay. MP3, M4A, AAC, FLAC, OGG, Opus, and WAV have explicit direct-delivery MIME policies; files require a current successful audio inspection and imported token. Original media remains read-only.

A real-library scan recovered from `entry_unreadable` after an operator-authorized read-permission adjustment on the affected source files. Verification confirmed that owners, groups, and all other permission bits were preserved; a traversal as the application user found no inaccessible files or directories. The retry completed successfully while technical inspection continues independently. Source mounts remain read-only; Bolognesa does not alter media permissions.

Music inspection now ignores video streams explicitly marked as attached cover art. FFprobe can report zero dimensions for such images while successfully identifying MP3 audio; previously this rejected the whole observation. A regression verifies accepted audio alongside that artwork, missing/invalid audio rejection, and unchanged default video validation. Focused probe tests passed (14 tests), and `mix precommit` passed with 451 tests and one skipped. The correction is published and deployed. Direct read-only probes accepted 30 affected files, and bounded recovery through the existing token-protected inspection use case persisted successful observations for all 30. The 19 initially reported tracks were verified imported against their current observations. The complete library rescan succeeded; remaining reinspection work continues in the background.

Automated controller tests exercised synthetic bytes for all seven extension/MIME mappings, ranges, HEAD, session revocation, source changes, and unsafe paths. These tests establish delivery, not decoding. The screenshot workflow verified generated 16-bit mono PCM WAV audio in Chromium from the pinned Linux Playwright container: play, seek, pause, and retained position after refreshing the music list. The music library, native player, and updated navigation captures were visually reviewed. No interactive browser was connected to the browser runtime, and local FFmpeg/FFprobe executables were unavailable; manual keyboard/touch checks, MP3 and other audio decoding, and device compatibility remain unverified. There is no music conversion, queue, album/artist screen, or playback continuity across navigation. The next delivery is artist/album browsing and ordered album playback; see the [roadmap](roadmap.md) and [decision 0018](decisions/0018-local-music-catalog.md).
